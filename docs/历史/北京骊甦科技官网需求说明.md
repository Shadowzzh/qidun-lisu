# 北京骊甦科技官网建设需求说明

Date: 2026-04-29
Status: Confirmed in chat
Project: `ai-website-cloner-template`

## 文档职责

本文件只定义项目目标、范围、约束和完成判断。

本文件不负责：

- 路由与栏目设计
- 页面与素材映射
- 页面模块拆解
- 当前阶段的实现优先级

上述内容分别由其他配套文档承担。

## 根目标

本项目的根目标，是基于仓库内现有内容归档，把当前网站模板演进为“北京骊甦科技”的正式多页面官网。

这里的重点不是把 PPT 页面搬上网，也不是把旧模板简单换一套文案，而是把现有方案型资料转译为一套更接近企业官网阅读方式的站点表达，让用户能够清晰理解：

- 北京骊甦科技是谁
- 北京骊甦科技提供什么方案
- 这套方案有哪些核心能力
- 这套方案为什么可信、可落地、可持续扩展

## 内容来源与事实边界

本项目当前唯一内容归档来源为仓库根目录下的 `archive/ppt-source`。

归档内容来自 PPT 文件 `企业级私有化AI知识智能平台方案-骊甦.pptx`，包括：

- 整体文案
- 分页文本
- 结构化文本
- 图片素材

这些内容是官网表达的唯一事实基础，用于整理、转译、追溯和对照。

因此必须遵守以下边界：

- 不新增 `archive/ppt-source` 之外的业务资料作为事实内容
- 不虚构客户、新闻、投资者信息、联系方式、备案信息或公司介绍细节
- 对当前资料中并不存在的内容，宁可留空、降级或改为说明型表达，也不补造事实
- 归档目录仅作为内容来源，不直接作为页面运行时公开资源路径使用

## 交付范围

本项目包含：

- 一套统一的北京骊甦科技官网站点壳
- 一套清晰的多页面官网结构
- 基于现有资料整理出的品牌、方案、能力、案例和团队表达
- 与北京骊甦科技业务语义一致的新路由体系
- 能支撑后续扩展的统一内容组织方式

本项目不包含：

- 引入新的外部业务资料
- 把 PPT 每一页原样转成网页
- 伪造新闻、动态、合作客户或资本市场内容
- 在没有事实支撑的前提下补齐完整公司信息页

## 强制约束

- 网站主体必须统一为“北京骊甦科技”
- 最终形态必须是正式多页面官网，不是单页展示稿
- 导航层级可以沿用现有目标站思路，但路由命名必须切换为新的业务语义
- 页面内容必须围绕“企业级私有化 AI 知识智能平台方案”展开
- 全站阅读体验必须更接近企业官网，而不是 PPT 顺序阅读
- 页面外层骨架、导航秩序和视觉节奏必须可统一维护

## 完成判断

当以下条件同时成立时，可认为需求方向成立：

- 用户进入网站后，看到的是北京骊甦科技的正式官网，而不是模板站或 PPT 在线版
- 网站具备清晰的多页面结构和明确的栏目分工
- 主要内容均可追溯到 `archive/ppt-source`
- 网站能够稳定承载方案、能力、案例和团队这四类核心信息
